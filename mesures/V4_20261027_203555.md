## Commentaire

V4 a confirmé la réplication (1 ligne de contrôle visible sur bdd1 et bdd2),
la promotion de bdd2 (`pg_is_in_recovery() = f`) et le rétablissement de
`/sante`. L'arrêt de bdd1 a duré 82 s ; la bascule a pris 70 s et l'absence
de réponses 200 a atteint 109,58 s sur cet hôte.

La vérification initiale de `/resultat` a renvoyé HTTP 400 parce que le script
cherchait le matricule sur bdd1 déjà arrêtée. Après correction du contrôle, une
requête manuelle avec un matricule lu sur bdd2 promue a renvoyé HTTP 200. Le
script V4 a été corrigé pour interroger bdd2 directement lors de cette
vérification ; le rapport conserve les mesures réellement prises.
